## 🏆 Best AI Product on 0G — $6,000 ($3,000 / $2,000 / $1,000)

*The Application track — "what you ship." AM I COOKED is the end-user product; SEAL
(below) is the separate Infrastructure submission.*

**0G's own thesis is "every action cryptographically verified instead of blindly
trusted." That's our whole product: a verdict you don't trust — you tap the seal and
verify it on-chain.**

Every wallet checker asks you to believe its score. Ours makes the score self-proving.
Paste a wallet at **tracely.live/cooked** and the AI verdict is:

- **Judged inside a 0G Compute TEE** (`qwen2.5-omni-7b`) with **per-response signature
  verification** — private inference, provably run where we say it ran.
- **Rubric-gated and rubric-frozen.** The scoring rules live in `contracts/rubric.md`;
  their hash was committed into the CookedRegistry constructor **at deploy**. Our
  sealing pipeline re-hashes the local rubric and reads the on-chain one — **if they
  differ, sealing refuses to run.** The rules cannot change after a wallet is scored.
- **Attested on-chain.** Each verdict's `scoreHash` is written to CookedRegistry on
  Galileo. Tap the wax seal in the app → the real `attest` transaction opens on the 0G
  explorer. (Idempotent — an identical verdict resolves to its original tx via the
  event log.)
- **Private by construction.** Scans are cached by a **hash of the address** (no
  plaintext ledger of who looked up whom); history is **encrypted in 0G Storage**
  (AES-256-GCM, client-side).
- **Identity for the fixer.** The Surgeon agent holds a minted **0G Agentic ID**
  (tokenId 2), metadata encrypted in 0G Storage (ERC-7857 draft surface).

**Why it scores:** it's a real end-user product on 0G Compute (not a stub), every 0G
capability is load-bearing, and the trust claims are independently verifiable in front
of the judge. Demo wallets are pre-sealed on-chain, so it answers in under a second.

**0G features / SDKs used (required field):** 0G Compute (Private Computer) — TEE

## 🏆 Best Infrastructure & Tooling on 0G — $4,500 (up to 3 teams, $1,500 each) · SEAL

*The Builder track — "what others build on." This is the framework layer; the app is
the separate Application submission. Different deliverable, same repo.*

**One config line gives any AI client private inference, permanent memory, and proof
of every answer — 0G, as MCP tools.**

We needed 0G in four places (judge inference, verdict memory, registry calls, agent
identity) and refused to scatter SDK imports through an isomorphic codebase. So we
built **SEAL**: a standalone MCP server that is the *only* thing in the repo that
speaks 0G. Our whole app imports **zero 0G SDKs** — everything flows through SEAL.

- **8 tools**, including `seal_infer` (TEE inference + attestation), encrypted 0G
  Storage memory, chain calls, and Agentic ID mint/load.
- **`seal_verify` is a trust primitive** — any agent can verify **another** agent's
  attestation, not just its own.
- **Dev-mode superpower:** the stub backend emits self-consistent *fake* attestations
  that `seal_verify` genuinely validates and rejects when tampered — so we built the
  entire product offline against the stub and flipped to live 0G **without changing a
  line of agent code**. That's a pattern the SDK itself could ship.
- **Working example agents** ship in the repo: `examples/goldfish.ts` and
  `examples/desk-check.ts`.
- **Architecture diagram** (mermaid, renders on GitHub) at the top of the README:
  app → SEAL (MCP) → 0G Compute / Storage / Chain, plus the World interlock.

**Why it scores:** it's genuinely reusable dev tooling — any Claude/Cursor/ChatGPT
client mounts it in one config block and inherits 0G. We're user #1 (the whole product
runs on it), which is the strongest proof a tool is real.

### Difficulties we hit and solved (say these — all reproducible)

- **Verifiable output from a 7B TEE model.** A chat model can't be trusted to do exact
  weighted-rubric math, and a sealed *wrong* answer is worse than no seal. We solved it
  with the **reference-verdict pattern**: compute the rubric math deterministically,
  give the model the reference alongside the surfaces, then gate its output through
  `parseVerdict`, which recomputes the score and rejects anything off-rubric.
- **Attestation semantics.** An unkeyed MAC proves record *integrity*, not TEE origin —
  so `seal_verify` reports `valid` only when a TEE signature was checked at response
  time, and says so. (Worth stating in the 0G SDK docs.)
- **The inference ledger needs the 3-OG network minimum on Galileo** — we found it by
  the deposit failing; worth printing in the quickstart.
